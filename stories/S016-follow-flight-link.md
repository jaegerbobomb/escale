## User story

> **As a** traveller, **I want** to send someone a link to follow my flight live,
> **so that** whoever picks me up knows when I land.

## Technical description

- On a flight segment: "Share flight", which shares (system share sheet, or copy) a
  Flightradar24 link built from the flight's callsign: the airline's **ICAO** code and
  the flight number (`AF 718` → `AFR718`).
- Flights only: Flightradar24 does not follow trains.
- Nothing is sent by Escale itself: the user chooses where the link goes (the app stays
  privacy-first).
- URL format, from a working link given by the maintainer (2026-11-24):
  `https://www.flightradar24.com/AFR718/42b64dc4`, i.e. `/<ICAO callsign>/<flight id>`.
  The flight id is Flightradar24's own id for one flight on one day: Escale cannot know
  it from the ticket. Without it, `/<ICAO callsign>` (e.g.
  `https://www.flightradar24.com/AFR718`) shows the flight while it is in the air and
  otherwise the list of its next flights (maintainer, 2026-11-24, from memory: to
  confirm on a real flight). Escale shares `/<ICAO callsign>`.
- ICAO code: kitinerary often gives only the airline's IATA code; Escale needs an IATA
  → ICAO table (source and licence to choose; must be GPL-compatible). A callsign is
  not always ICAO code + flight number: when unsure, share no link rather than a wrong
  one.

## Acceptance Criteria

### Scenario: Sharing a flight

* **Given** a flight segment AF 718
* **When** the user shares it
* **Then** the shared text holds a Flightradar24 link for AFR718

### Scenario: No link for a train

* **Given** a train segment
* **Then** no "Share flight" action is shown

### Scenario: No link when the airline is unknown

* **Given** a flight segment ZZ 12 of an airline missing from the table
* **Then** no "Share flight" action is shown

## Notes

- Asked by the maintainer (2026-11-24); validated (`todo`) once the link behaviour was
  known.
- Delivered in 0.12.0. "Share flight" sits in the flight's detail (S011), next to
  "Ticket". On Android and iOS it opens the share sheet (`ft.Share`); elsewhere it copies
  the text (`ft.Clipboard`) and says "Link copied". Checked in a browser on the
  `/flight-detail` demo route: the clipboard holds
  `Follow flight AF 718: https://www.flightradar24.com/AFR718`.
- IATA -> ICAO table: `escale_core/data/airlines.csv`, 830 airlines, generated by
  `tools/airlines_from_wikidata.py` from Wikidata (CC0, so GPL-compatible): best-rank
  P229/P230 statements without end date, airlines without dissolution date (P576).
  When several airlines share an IATA code, the one with at least twice the sitelinks of
  the next is kept (Lufthansa over Lufthansa Cargo); otherwise the code is left out and
  no link is shown. Leading zeros of the flight number are dropped (`AF 0718` ->
  `AFR718`).
- Known limit: some airlines (low-cost carriers especially) fly under alphanumeric
  callsigns that differ from the flight number; the link then finds no flight in the
  air. Not detectable from the ticket. Flightradar24's flight-number pages
  (`/data/flights/af718`) might avoid this; not verified (the site is not reachable from
  the build environment), to look at if users report it.
- The detail's actions now sit on their own row under the title, so that "Ticket" and
  "Share flight" fit at 380 px.
